# Предиктивное моделирование LER/LWR при фотолитографии (DUV, 193/248 нм)

Настольная программа: Qt-интерфейс на Python, вычислительное ядро на C++ (OpenMP).
Работает без сети. Свойства резиста условные, не калиброваны по измерениям.

## Состав

| Путь | Назначение |
|---|---|
| `ler_gui.py` | окно программы |
| `lercore/lercore.cpp` | ядро C++: экспонирование, термообработка, проявление; повторные расчёты параллельно |
| `lercore/build.py` | сборка ядра в `lersim/_lercore*.pyd` |
| `lersim/process.py` | цепочка расчёта; эталонная реализация на NumPy и вызов ядра C++ |
| `lersim/core.py` | метрики краёв, спектры, аппроксимация спектра |
| `lersim/sweep.py` | окно процесса: ширина линии и шероховатость по сетке доза × фокус |
| `lersim/stats.py` | статистическая оценка: среднее, доверительный интервал, интервал предсказания, вклад нестабильности процесса |
| `docs/руководство.html` | руководство пользователя (открывается из программы по F1) |
| `lersim/figs.py`, `style.py` | графики |
| `tests/white` | тесты «белый ящик»: каждая функция против точных аналитических ответов |
| `tests/black` | тесты «чёрный ящик»: выходные данные, физические тренды, эталон, программа целиком |
| `run.py` | пакетная проверка генератора шероховатости |

## Рабочее место (VS Code)

Открыть `ler_sim.code-workspace`, затем `Terminal → Run Task…`:

1. «Создать окружение .venv» — один раз, нужен интернет.
2. «Собрать ядро C++» — нужен компилятор MSVC (Visual Studio или Build Tools, компонент «Разработка классических приложений на C++»). Без него программа работает на ядре Python.
3. «Запустить приложение» или `F5`.
4. `Ctrl+Shift+B` — сборка `dist\LER_sim\LER_sim.exe` и архива `dist\LER_sim_win64.zip`.

Все временные файлы и кэши пишутся в `.cache` внутри проекта; «Освободить место на диске C» (`tools\free_c.bat`) показывает, что занимает место на C, и по каждому пункту спрашивает, удалять ли.

## Производительность

Ядро C++ хранит поля в float с выравниванием строк по кэш-линии (64 байта) и делает шаг термообработки
за один проход по памяти (свёртка по x в кольцевой буфер в кэше L1, из него сразу свёртка по y и реакция).
Параллельно: строки сетки при PEB, 16 полос строк при проявлении, реализации и точки окна процесса —
по одной на поток. Результат побитово не зависит от числа потоков.

При запуске `lersim/hw.py` анализирует компьютер (ядра, свободная память, замер скорости) и выбирает
число потоков: все логические ядра, кроме одного для интерфейса, с ограничением по памяти. На медленном
компьютере (реализация дольше 1 с) автоматический пересчёт отключается. Число потоков задаётся и вручную
(«Расчёт → Параметры численного расчёта»).

## Журнал и данные

Рядом с программой создаётся папка `logs`:

- `журнал_ГГГГ-ММ-ДД.txt` — каждый расчёт по этапам с промежуточными величинами и временем;
- `история_расчётов.csv` — все параметры и результаты каждого расчёта, открывается в Excel.

Таблица результатов, контуры краёв и графики экспортируются из меню «Файл».

## Тесты

`Terminal → Run Task…` → «Тесты: все», «Тесты: белый ящик» или «Тесты: чёрный ящик».

После **полного прогона** («Тесты: все» или сборка EXE) в `logs` появляются:

- `отчёт_тестов_ДАТА.html` — подробное ревью каждой проверки: что и как проверяется, критерий
  прохождения, зачем это нужно, таблица измерений «получено / ожидается / в норме», вывод, время,
  при ошибке — вывод pytest, код проверки; сводка по разделам и сведения о среде выполнения;
- `отчёт_тестов_ДАТА.csv` — одна строка на проверку, для Excel;
- `отчёт_тестов_ДАТА_измерения.csv` — одна строка на измерение.

Частичный прогон (один набор или отбор по имени) пишет краткий `отчёт_тестов_ДАТА.txt`.

Каждый тест записывает измерения фикстурой `rec`; описание берётся из строки документации теста
(первая строка — заголовок, далее разделы «Метод:», «Критерий:», «Зачем:»).

**Белый ящик** знает устройство модели и сверяет каждую функцию с точным ответом: изображение трёх
дифракционных порядков, реакция в однородном поле, сохранение кислоты при диффузии, плоский фронт и
одномерный предел уравнения эйконала, обход нерастворимой ячейки, Парсеваль, восстановление параметров
спектра, квантили Стьюдента, независимость ядра C++ от числа потоков.

**Чёрный ящик** видит только вход и выход: диапазоны и согласованность выходных величин, физические
закономерности (доза, фокус, температура, время, апертура, длина волны, закон 1/√V для дробового шума),
симметрии, сходимость по сетке и шагу PEB (`test_convergence.py`), совпадение двух вычислительных ядер,
эталонные значения (`tests/data/golden.json`) и работа программы: таблица, журнал, история в CSV,
сохранение параметров, кэш.

Эталон пересоздаётся только после осознанного изменения модели: `python -m tests.make_golden`.
