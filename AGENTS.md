# Инструкции для ИИ-агента

Проект: предиктивное моделирование LER/LWR при DUV-фотолитографии (193/248 нм). Настольная программа
для закрытого контура: Qt (PySide6-Essentials) + вычислительное ядро C++ (pybind11, OpenMP), сборка в EXE
через PyInstaller. Сеть, браузер, localhost, SciPy, WebEngine не использовать.

## Структура
- `ler_gui.py` — окно программы (параметры, графики, таблицы, журнал, окно процесса, статистическая оценка).
- `lersim/process.py` — цепочка: изображение → экспонирование (Пуассон/бином) → PEB (облака молекул r_c, 30 шагов,
  трапеции) → проявление (Мак, двумерный фронт: эйконал, быстрые проходы) → метрики. Сетка 1 × 1 нм.
- `lersim/core.py` — метрики краёв, спектры, аппроксимация Паласанцаса (свой Левенберг–Марквардт).
- `lersim/sweep.py` — окно процесса (полный стохастический расчёт с общими случайными числами); `lersim/stats.py` — среднее, ДИ, интервал предсказания, вклад нестабильности процесса.
- `lersim/figs.py` — графики; `lercore/lercore.cpp` — ядро C++ (float, строки выровнены по 64 байта, генератор на строку).
- `docs/руководство.html` — руководство пользователя; `tests/white`, `tests/black` — тесты.

## Стиль кода
- Плотный код без шаблонных комментариев и докстрингов «для галочки»; комментарии только по физике и математике.
- Имена переменных физические: `sigma`, `xi`, `alpha`, `CD`, `dx`, `dy`, `L_D`.
- Без `try/except` на всё подряд — только там, где ошибка реально ожидается (файлы, ввод пользователя).
- Единицы: нм, с, °C, мДж/см², концентрации в нм⁻³.

## Подписи (академический стиль)
- Оси: «Величина символ, единица»; переменные курсивом (`$E$`, `$\Delta z$`), аббревиатуры прямо (CD, LER, NILS).
- Десятичная запятая на графиках, в таблицах, журнале и CSV; минус «−»; панели «а)», «б)» без заголовков.
- Весь интерфейс и журнал на русском, понятными словами, без внутренних имён переменных.

## Тесты
- Запуск: `python -m pytest -q` (задача VS Code «Тесты: все»). Полный прогон пишет отчёт HTML/CSV в `logs`.
- Каждый тест записывает измерения фикстурой `rec(имя, значение, ожидается, единица, условие)` и
  проверяет `assert rec(...)`.
- Докстринг теста: первая строка — заголовок; далее разделы «Метод:», «Критерий:», «Зачем:».
- Эталон `tests/data/golden.json` пересоздаётся только при осознанном изменении модели: `python -m tests.make_golden`.
- Новый параметр, величина или график должны быть описаны в `docs/руководство.html` (это проверяет тест).

## Сборка
- `setup_env.bat` → `build_core.bat` → `build.bat` (Ctrl+Shift+B): ядро C++, тесты, EXE, архив.
- Все кэши и временные файлы на диске D (`env_d.bat`), не на C.
- После изменения `lercore.cpp` пересобрать ядро и прогнать `tests/white/test_cpp.py` и `tests/black/test_contract.py`.

## Физическая модель
- Допущения перечислены в `docs/руководство.html`, раздел 4; любое изменение модели — с обновлением этого раздела.
- Сходимость по сетке и шагу проверяет `tests/black/test_convergence.py`; изменение схем не должно её ухудшать.
- На панели только параметры процесса; свойства резиста — из файла параметров (вкладка «Резист» только показывает).
